  原 HTTP 请求预留、输出限制、SDK 重试、主/辅助共账本、未知用量停止规则未改。

冻结对账及下一请求预留均发生在下一任务 materialize/worker 之前。
正式批次不是可恢复任务队列：重复输出目录、已登记批次、已启动/不确定 attempt 不自动重试。

### 失败证据与唯一优先改进方向

**T07：需求边界自测遗漏。** 最终补丁 `textkit/slug.py` 用 `[^\w\s-]+` 删除标点，

独立 `test_unicode_empty` 中 `A_B` 得到 `a_b`，而非 `ab`，因此目标 3/4。
Agent 生成了多种 Unicode、空输入、空白和连字符测试，却没有这一字符类别边界；
sidecar trace 的 `accept/verifier_ok`（第 196 行）也未捕获它。
证据来自保存的 [T07 补丁](../../evaluation/linux_baseline/results/p2-live-20260909-062500/T07.patch)、
冻结目标结果和 trace 哈希；未将隐藏反馈喂回 Agent，未补改首次补丁。

**T09：预算限制截断测量。** 证据是账本 request_id 6–17 的发送前拒绝，以及五个成功结算响应。
不能据空补丁断言 Agent 不会实现投影功能，也不能归因为 Provider 不可用或 sidecar 回归。
其他五题通过本任务集的冻结验收，样本仍只是两个本地 fixture。

**下一步唯一优先方向：让显式需求的类别约束驱动对抗性边界自测。**
